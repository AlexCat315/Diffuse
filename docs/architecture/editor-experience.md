# GuavaStudio Editor 界面与行为设计

本文是 [工作站边界](workstation.md) 的交互补充：那份文档定义“有什么”，这份定义“看起来怎样、按下去会发生什么”。所有条目都落在现有结构上——统一工作台、`EditorCommandCatalog` 单一命令源、`EditorVisualTheme` 单一令牌源——不新增平行列表。

## 1. 设计原则

1. **一个动作，一处反馈。** 用户触发的动作必须在动作发生的地方或窗口级通知中得到回应；控制台是历史记录，不是唯一的反馈渠道。
2. **被拒绝时说明原因并给出出路。** “试玩中不能编辑”不是终点，通知里直接提供“停止试玩”。
3. **布局稳定。** 状态变化（复制成功、筛选为空、试玩开始）不推挤周围内容；临时信息放在浮层或固定槽位。
4. **键盘可达。** 菜单里出现的每个动作都能被命令面板搜到；常用区域切换有快捷键；同一个快捷键在所有投影里一致。
5. **点击即切换。** 活动栏、Space、播放这类“开关型”入口，再次点击当前项回到之前的状态，而不是无响应。
6. **上下文跟随 Space。** 写作 Space 的上下文是当前文件，场景 Space 是当前实体；标题栏、意图框、Agent 输入框、命令面板读同一个上下文。
7. **卡片契约：用层级和间距分区，不用线。** 界面只有三层——窗口底色、面板、卡片；每个独立部分都是一张卡片，彼此用间距分开。分隔线只保留在逐行对齐的表格（快捷键表）和浮在 3D 视口上的浮层描边。

## 2. 视觉语言

| 元素 | 规则 |
| --- | --- |
| 第 0 层：底色 | `background`（深色 #141716，浅色 #E3E8E5）；标题栏、活动栏、状态栏、设置窗口的分类栏直接画在上面 |
| 深色梯度 | 炭灰而非纯黑：底色 #141716 → 面板 #1D2120 → 卡片 #272C2A → 选中 #333A37，每层约一档亮度差；正文 #ECEFED、次要 #B6BEBA、弱化 #8B948F，保证在卡片上仍可读 |
| 第 1 层：面板 | GuavaUIWorkspace 唯一的面板外观：`surface` 填充、`radius.lg`（10pt）圆角、无边框无阴影；面板之间 6pt 间隙，工作区右侧留 6pt |
| 第 2 层：卡片 | 面板里每个独立部分是一张 `surfaceRaised`、`groupRadius`、无描边的卡片：属性分组（PropertyGrid 只有卡片一种分组）、Agent 建议、日志条目；卡片之间 6–8pt 间距，卡片内不再嵌卡片，子分组平铺 |
| 面板内部 | 工具栏与内容之间不画分隔线，标签栏没有单独的表头底色；输入框用 `surfaceSunken` 凹入 |
| 标签 | 所有分组和文档标签都是圆角选中块，不用顶部选中线，也不在标签之间画竖线 |
| 设置窗口 | 同一套语言：标题栏、分类栏、搜索与底栏在底色上；搜索框和每个设置分组是无边框圆角块；只有快捷键表保留逐行分隔线 |
| 浮层 | 菜单、命令面板沿用 `surfaceRaised`；通知强制不透明，避免透出下方文字 |
| 视口 | 参照 Unreal 的视口菜单：场景画面上只有视图立方体，控件都在场景上方的标题行。左侧是“指针做什么”——工具分段轨道、局部/世界、吸附（开启时着色）；右侧只有两个以当前值命名的菜单，不带下拉箭头：“透视”（投影、视角子菜单、聚焦选中 F、重置视图、逐步导航子菜单）和“光照”（着色模式、调试视图子菜单、参考网格、阴影、渲染比例子菜单、物理调试子菜单）。菜单项都在菜单自己的浮层里，不在菜单外挂面板；物理调试各层在说明行写出对应颜色 |
| 组件卡片 | 重置/移除放在各组件卡片标题的 `⋯` 菜单里，属性面板底部只留“添加组件”；属性搜索的计数只在搜索时出现；一行提示或折叠项按内容高度排版，不套控件最小高度 |
| 脚本 | 参照 Unity 的组件模型：每个脚本就是一张组件卡片，不再套在“脚本”容器里。标题行是脚本图标、名称、状态圆点、启用开关、`⋯`（打开、更换、移除）；第一行是“源文件”引用框，点开源码；构建或接口消息是卡片内的提示块；随后才是脚本自己的属性，高级参数是 caption 字号的折叠项。脚本通过“添加组件”里的“脚本”分类添加，不单独放“添加脚本”入口，也不提供空的脚本组件 |
| 树形选择 | 大纲和文件的选中行是内缩圆角块（左右各 6pt、圆角 6），用淡强调色，不用整行色块和左侧竖条；行高 26 |
| 文件图标 | 文件树、文档标签、路径栏、标题栏面包屑和上下文芯片用 Catppuccin 彩色文件图标（MIT，`Editor/Sources/EditorUI/Resources/FileIcons`，深色用 mocha、浅色用 latte），保持原色不着色；`DocumentKind` 是唯一的类型表，先认整个文件名（README、LICENSE、Makefile、CMakeLists.txt、Dockerfile、package.json…）再认扩展名，覆盖 66 种类型，没有对应时用通用文件图标 |
| 终端 | 底部分组里的“终端”面板（GuavaUITerminal，ghostty-vt），所有 Space 都有；每个项目窗口一个登录 shell，在项目目录启动，切换标签或 Space 不会重启；进程退出后底部出现“重新启动”。从活动栏、窗口菜单或 ⌘K 打开 |
| 收起与活动栏 | 收起的区域不再留一列标签图标条（`WorkspaceTheme.showsCollapsedRails = false`），只由左侧活动栏打开；活动栏覆盖所有可收起面板（大纲/文件、属性、Agent、日志、资源、控制台、终端）。状态栏不再常驻绿色连接点，只有断开时出现提示点 |
| 文档标签 | 照 VS Code：未保存的标签显示一个小圆点，悬停变成关闭；已保存的标签只在选中或悬停时显示关闭；路径栏只显示路径，不再有“保存”和“⋯”（保存用 ⌘S，放弃/关闭在文件菜单和文件树右键） |
| 标签拖拽 | 拖动面板标签时显示落点预览和跟随指针的标签；预览挂在工作区自己的标记节点上，宿主改调试名不会让它失效。标签条刚好放满时不显示横向滚动条 |
| 原生窗口按钮 | macOS 红绿灯按应用标题栏高度（40pt）垂直居中，窗口缩放、退出全屏和切换焦点后重新对齐 |
| 分栏间隙 | 区域之间和区域内部的分栏都只留画布间隙，不画分隔线；拖动分栏后也不会留下细线 |
| Swift 标签页 | 项目脚本在文档标签页中编辑，带定义、实现、引用、后退/前进、声明层级面包屑、语义关系箭头和快速修复灯泡；详见 [Swift 语言支持](../components/swift-language-support.md) |
| 脚本面板并入编辑器 | 原“脚本”面板删除：构建状态与“构建”、信任、外部打开、删除收进 Swift 标签路径栏；新建与删除脚本也在文件树里。游戏 Space 默认包含文件和编辑器面板，“场景与脚本”布局把编辑器放在场景右侧 |
| 插件设置 | 已安装插件一行一项：图标、名称、版本、说明、权限徽标和开关，更多操作收在“⋯”里；内置 Swift Support 停用后仍保留在列表中。添加插件先出现审核卡片：能力与可运行命令直接列出，哈希等完整性信息折叠 |
| 动效 | 所有自绘按钮与行（标题栏、活动栏、视口控件、设置导航与选项、播放、文件树 / 大纲行、文档标签与未保存圆点）在悬停、按下、选中和焦点变化时用主题 `.fast`（默认 80ms）过渡；横幅、结果条、错误提示、插件审核卡片和语言服务提示以淡入加高度展开出现、收起消失，不再把下方内容一下推开。减少动画时全部直接到终态 |
| 滚动条 | 不足 0.5pt 的溢出视为取整误差，不显示滚动条（标签条等刚好放满的条带不再出现横向滚动条） |
| 修饰顺序 | GuavaUI 的 padding/background 作用在同一节点上：要在带背景的块外再留边距，必须再包一层，否则第二个 padding 会替换第一个 |

## 3. 窗口结构

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 标题栏 40pt  [项目▾] 分支  面包屑 │ ✦ 意图框 ⌘K @上下文 │ Spaces │ 在场 │ 运行 │
├────┬─────────────────────────────────────────────────────────────────────┤
│活动│ 左侧栏          │ 中央（视口 / 编辑器 / 时间线）     │ 右侧栏          │
│栏  │ 大纲·文件·资源  │                                     │ 属性·Agent·日志 │
│44pt│                 ├─────────────────────────────────────┤                 │
│    │                 │ 底部：控制台·动画·渲染·开发者工具   │                 │
├────┴─────────────────────────────────────────────────────────────────────┤
│ 状态栏 24pt  ● 问题 │ Space │ 文档状态 ……………… 光标 │ 后台活动 │ Agent     │
└──────────────────────────────────────────────────────────────────────────┘
                                                     ┌ 通知 360pt（右上）┐
```

窗口级浮层自下而上：Portal（菜单、Popover）→ 通知 → 命令面板 → 未保存对话框。通知锚在工作区右上角，位于标题栏下方，不遮挡标题栏的运行控件。

## 4. 区域行为

### 4.1 活动栏

| 行为 | 规则 |
| --- | --- |
| 点击未激活的面板 | 展开所在分组并激活该面板（现有行为） |
| 点击已激活且展开的面板 | **收起所在分组**；再次点击恢复 |
| 图标 | 每个入口唯一：大纲 `list`、文件 `folder`、资源 `package`、Agent `sparkles`、日志 `git-commit`、控制台 `panel-bottom` |
| 选中指示 | 左侧 2pt 叶绿竖线 + `surfaceVariant` 底；Agent 用玫红墨色 |

### 4.2 区域开关

左、右、底三个停靠区都可以整体收起和展开，作用于该区域内所有分组（包括“渲染工具”“脚本编辑器”这类拆分出的分组）：

| 命令 | macOS | Windows / Linux |
| --- | --- | --- |
| 切换左侧栏 | ⌥⌘L | Ctrl+Alt+L |
| 切换右侧栏 | ⌥⌘R | Ctrl+Alt+R |
| 切换底部面板 | ⌘J | Ctrl+J |

区域内任一分组展开时视为“展开”，命令收起全部；全部收起时命令展开全部。命令位于“视图 → 面板”，命令面板可搜索“侧栏 / 底部 / sidebar / panel”。

### 4.3 运行

| 命令 | 快捷键 | 说明 |
| --- | --- | --- |
| 试玩 / 暂停 | ⌘↩ | 现有 |
| 停止 | ⇧⌘↩ | 新增；仅在试玩或暂停时可用 |
| 构建 / 构建并运行 | ⌘B / ⌘R | 现有 |

切换到不支持试玩的 Space 时，编辑器会先停止试玩；此时发出一条“已停止试玩”通知，避免用户以为游戏仍在运行。

### 4.4 通知（新增）

`EditorNotifications` 持有一个窗口级 `ToastController`（同屏最多 3 条），由根视图挂载一次 `NotificationHost`。它只是 GuavaUI Toast 的边界适配，不进入持久状态。

| 事件 | 语气 | 时长 | 操作 |
| --- | --- | --- | --- |
| 保存场景 / 保存文件成功 | success | 2 s | — |
| 保存失败 | error | 直到关闭 | 打开问题 |
| 布局已保存 / 已重置 | info | 2 s | — |
| 因试玩被拒绝的编辑（复制、删除、添加、提交 Agent 请求） | warning | 5 s | 停止试玩 |
| 没有可重新打开的面板 | info | 2 s | — |
| 控制台复制 | success | 2 s | — |
| 切 Space 导致试玩停止 | info | 3 s | — |

同一类事件使用稳定 ID（如 `save`、`playback-blocked`），连续触发时替换而不是堆叠。所有通知仍写入控制台，问题计数和历史不变。

### 4.5 命令面板（⌘K）

- 输入框左侧的图标随作用域变化：意图 `sparkles`（玫红）、`>` 命令 `terminal`、`@` 资源 `file`、`#` 实体 `box`。
- 上下文芯片跟随 Space：写作 Space 显示当前文件名，场景 Space 显示选中实体。
- 结果行：有说明时 48pt 两行，没有说明时 36pt 单行；快捷键用 `caption` 字号的键帽样式，与标题栏意图框的键帽一致。
- 空查询时先列出最近执行的命令（本次会话内，最多 5 条，不持久化）。

### 4.6 Agent 面板

- 工具栏的“清空对话”使用 `trash` 图标；`more` 图标只用于真正的菜单。
- 输入框上方的上下文芯片与命令面板一致：写作 Space 显示文件，场景 Space 显示实体。
- 发送按钮不可用时，提示行说明原因（未连接服务商 / 试玩中 / 等待审阅），取代固定的“应用前审阅”文案。
- 起始建议随 Space 变化：写作——“总结这个文件”“找出这个文件的问题”；场景——“解释当前选择”“帮我规划下一步”；通用——“找出项目中的问题”。

### 4.7 标题栏

- 在场头像不再在 24pt 圆里放文字“你/You”（中文与长语言会溢出），改为 `user` 图标；Agent 头像保持 `sparkles`，工作时显示玫红描边。
- 右侧控件簇（Spaces、在场、运行）始终贴住窗口右缘；空余空间只出现在意图框和 Spaces 之间。标题内容以 100% 宽度为基准再收缩，压过窗口外壳自带的拖拽区，所以剩余宽度不会落在最右侧。
- 分支名最宽 110pt，超出省略，不再压到面包屑上。
- 验收截图要记得：DevTools 截图不含 macOS 原生红绿灯，左侧 76pt 空白是它们的位置，不能据此判断左右对称。
- 其余密度与断点保持 [工作站边界](workstation.md) 的规定。

### 4.8 写作 Space 的编辑器

- 路径栏只保留路径、未保存标记、保存与更多操作；语言、编码、换行符只出现在状态栏，避免两处重复。
- 已修改标签的圆点在悬停时显示为关闭图标（点击仍先询问是否保存）。

### 4.9 状态栏

- Space 段落使用完整本地化的标题（不拼接英文 “Space”）。
- 点击 Space 段落打开 Space 菜单，与标题栏的窄窗口菜单相同。

### 4.10 控制台

- “已复制 N 条消息”改为通知，不再插入一行推挤列表。

## 6. 验收

- 单元测试：`guava test Editor --filter ...` 覆盖命令目录（新命令出现在“视图 → 面板”、快捷键唯一、不在不授权的 Space 出现）、区域开关的收起/展开语义、活动栏再次点击收起。
- 原生验收：`guava run Editor --devtools --no-open -- --project-dir <项目>` 后按 `query → input → query → capture` 检查：⌘J 收起底部面板、试玩中按 ⌘D 弹出带“停止试玩”的通知、⌘K 在写作 Space 显示文件上下文。
- 截图对比 390/1040/1440pt 三种宽度，确认通知不遮挡运行控件、标题栏顺序不变。

# GuavaStudio 工作站边界

GuavaStudio 是产品；`Engine/` 是场景、物理、渲染、脚本和 AI 等可复用运行库的实现目录。根 SwiftPM 工作区名为 GuavaStudioWorkspace，启动产品为 `GuavaStudio`。Editor 的包名为 GuavaStudioEditor，运行库包名为 GuavaStudioRuntime；资源 bundle、安装校验、发行包和官网使用对应的新标识。

## 生产领域

Editor 使用统一工作台。场景、脚本、大纲、属性与 Agent 共用文档、选择和布局；不再区分 Agent/manual 界面或持久化交互模式。工作流由 EditorWorkspaceProfile 定义面板与授权工具范围：

| 工作流 | 文档/操作 | 主要入口 |
| --- | --- | --- |
| Text and Code | 项目中的普通 UTF-8 文件，不隐式编译或执行 | DocumentsPanel、list/read/write_file |
| Video Editing | 视频源、顺序 cuts、裁剪、排序、预览/播放与 MP4 导出 | MediaTimelinePanel、媒体项目工具 |
| Game Development | 场景、游戏脚本、模拟和游戏构建 | 原有场景/脚本能力 |
| 3D Creation / Animation | 模型、渲染与动画组件 | 原有创作面板和能力 |

## 工作台界面

标题栏集中项目、当前选择、意图入口、五个 Space 和播放控制。写作、玩法、动画、剪辑、渲染依次使用 ⌘/Ctrl+1–5；脚本开发在“视图 → Space”里。窗口宽度小于 520pt 时，播放控制收成一个试玩/暂停按钮和停止按钮。

### 命令目录

所有可执行的编辑器动作只在 `EditorUI/Commands/Catalog.swift` 声明一次：标识、标题、搜索关键词、快捷键、所在菜单和可用条件。下面四处都是这份目录的投影，不各自维护列表：

| 投影 | 位置 | 说明 |
| --- | --- | --- |
| macOS 菜单栏 | `Shell/Menu/Native.swift` | 关于、设置放在应用菜单；“视图”下的 Space 和布局是子菜单；隐藏、退出等系统项由 GuavaUI 追加并本地化。 |
| Windows / Linux 标题栏菜单 | `Shell/Menu/TitleMenu.swift` | 沉浸式窗口在客户区绘制标题栏，Win32 菜单条会落在它下方，所以两个平台在标题栏最左侧放一个菜单按钮，每个顶级菜单是一个子菜单；设置并入“编辑”，关于并入“帮助”。 |
| ⌘/Ctrl+K 命令面板 | `ai/EditorCommandSearch.swift` | 列出目录中的全部命令，只去掉打开面板自身的三项（意图、命令、资源）。 |
| 窗口内快捷键 | `Root/Chrome/ShortcutHandler.swift` | 按物理按键匹配目录中的快捷键。主修饰键同时接受 Command 和 Control；不可用的命令吞掉按键但不执行；Esc 关闭面板，面板打开时回车留给输入框。 |

顶级菜单依次是文件、编辑、选择、世界、视图、Agent、运行、窗口、帮助。工作区不授权的命令直接不出现，而不是显示为灰色：影视 Space 没有试玩和构建；文本 Space 没有场景、选择和世界命令，⌘S 保存当前文件，另有“放弃修改”和 ⌘W“关闭文件”。“选择”和“世界”只在有场景的 Space 出现，复用大纲已有的场景操作（全选、反选、选择子级、添加实体、聚焦、显示/隐藏、锁定）。全选不占用 ⌘A，因为文本框需要它，而文本框只把撤销和重做交给原生菜单。过滤后为空的子菜单和多余分隔线也一并去掉。窗口菜单的面板名称与标签页标题共用 `EditorRootViewFactory.localizedPanelTitle`。

### 写作 Space

左侧“文件”面板是项目文本文件的文件夹树（文件夹在前，按名称排序，顶层文件夹和选中文件的上级默认展开），打开的文件带圆点，未保存的带黄色 M，右键可打开、保存、放弃修改或关闭；游戏 Space 里搜索栏旁的“新建脚本”和 Scripts 文件夹右键可新建脚本，脚本文件右键可删除（会先确认）。中间“编辑器”每个打开的文件一个标签，下面一行只有路径（语言、编码、换行符只在状态栏显示）；关闭未保存的标签会先问是否保存。项目脚本在同一个编辑器里编辑，路径栏右侧是构建状态、“构建”按钮和“⋯”（构建并重载、新建、外部打开、在访达中显示、信任/撤销信任、删除），未信任项目和磁盘变更提示显示在代码上方；不再有单独的“脚本”面板。其他 Swift 文件使用同样的 tree-sitter 着色和折叠，Markdown 使用源码与预览分栏。没有打开文件时显示居中的空状态和“打开文件 ⌘P”。编辑器面板设置 `hidesTabBarWhenAlone`，独占中央分组时文件标签就是顶部标签行，不再叠一行面板标题；Markdown 源码与 Swift 共用 13/20 等宽字体。⌘P 的资源搜索包含项目文件。文件、编辑器、标题栏和状态栏都观察 `EditorDocumentWorkspace.snapshot`（文档、选中文件和错误），切换已打开的文件也会立即同步。

标题栏面包屑跟随当前 Space：文本 Space 显示当前文件路径，场景 Space 显示“场景 › 选中实体”；意图框里的上下文芯片同样取自它。项目标识是项目名的两个首字母，旁边显示项目所在 git 仓库的分支。活动栏和状态栏通过 `Observed(\.version, on: controller)` 观察布局，切换 Space 后立即显示该 Space 的面板。

### 状态栏

状态栏左侧是连接状态、错误与警告计数（点击打开“问题”）、当前 Space，以及当前 Space 的文档状态：场景 Space 显示场景未保存标记、版本和选中数量，文本 Space 显示当前文件是否未保存，右侧再显示语言、编码和换行符；右侧是脚本光标位置、后台活动和 Agent 状态。后台活动按优先级显示进行中的操作（带进度）、脚本编译、最近一条警告或错误，空闲时不显示。Agent 状态依次显示待审阅数量、执行中、就绪或未连接，点击打开 Agent。错误与警告计数和控制台“问题”标签共用 `EditorProblemSummary`，两处数字始终一致。

左侧 44pt 活动栏直接打开大纲、搜索、Agent、会话日志、资源和控制台、终端；再次点击正在显示的面板会收起它所在的分组。“视图 → 面板”用 ⌥⌘L、⌥⌘R、⌘J 整体收起或展开左、右、底部停靠区，试玩中 ⇧⌘↩ 停止。默认布局将大纲、资源和文件放在左侧，场景与编辑器放在中央，控制台等工具放在中央下方；右侧只有属性、Agent、日志三个标签。待确认操作直接显示在 Agent 对话顶部，审阅命令也打开 Agent，切换面板不丢失草稿或确认状态。面板继续支持拖拽、分屏、折叠和恢复。保存过的自定义布局继续保留，使用“重置布局”应用新的默认分布。

所有分组的标签都使用紧凑选中块；文档标签同样是圆角选中块。各组的面板选择、最大化和收起统一放在尾部菜单中，避免右侧标签被工具按钮挤掉。控制台在筛选行切换日志、问题、构建输出，保留现有输出状态与问题导航；属性网格使用平整分节，普通 GuavaUI 应用继续使用默认卡片样式。

保存、布局、试玩拦截等用户动作的结果通过工作区右上角的通知反馈（`Shell/Notifications.swift`），控制台仍保留完整记录；试玩中被拒绝的场景编辑在通知里提供“停止”。交互细节见 [Editor 界面与行为设计](editor-experience.md)。

Editor 使用工作区唯一的面板外观：圆角面板浮在更深的窗口底色上，彼此之间留 6pt 间隙而不画分隔线；标题栏、活动栏和状态栏直接放在底色上，不再用分隔线隔开；面板内部的工具栏与内容之间也不画分隔线。通用 Workspace 的卡片外观保持为默认值。工作台颜色、12pt 正文/11pt 辅助文字、5–9pt 控件圆角由 EditorVisualTheme 管理，深浅主题共享语义样式。叶绿表示选择与编辑动作，粉色表示 Agent 入口。场景编辑采用深色 studio 背景，试玩采用天空；此设置属于渲染呈现，不进入场景文件。

⌘/Ctrl+K 是统一意图入口：普通文本交给 Agent，`>` 搜命令，`@` 搜资源，`#` 搜场景实体；命令与资源搜索不依赖 AI 服务。Agent 使用现有任务与确认管线，草稿由当前项目的面板注册表持有，切换属性/Agent 标签不丢失输入。日志显示真实的任务、操作和控制台活动。风险四级、跨系统窗口的镜头撕出、统一时间轴和配方属于独立的运行时架构阶段。

界面回归覆盖标题栏密度、连续缩放后的控件顺序、右侧上下文切换、文档与选择保持、草稿保留、五个快捷键以及紧凑属性栏三轴输入。Space 导航用稳定的布局槽承载标签、图标与菜单三种呈现，切换时不改变标题栏顺序。原生验收通过 DevTools 的 query → input → query → capture，调整最大化窗口时先恢复窗口再设置逻辑尺寸。

`EditorWorkstation` 组合三个服务：scripts、documents、media。项目脚本作为文档标签打开，但文本归 scripts 所有；标签的保存、还原、关闭、新建和删除都经由 workstation 的入口按归属分派，切换标签不会自动保存。普通文档的路径、UTF-8 和磁盘冲突规则由独立 `Editor/Documents` 包管理；UI 模型只是边界适配器。媒体解码/剪辑来自独立 `Engine/Media` 包。已有 EditorApplication 不再新增并行脚本/文档字段。

Agent 与 MCP 共用 executeProjectTool，不把文件操作伪装为 scene mutation。文本工作流不暴露场景变更能力；媒体工作流提供读取时间线、添加/裁剪/移除 cuts、保存和导出。现有文件写入要求 read_file 返回的完整 expected_text，并拒绝覆盖未保存缓冲区或磁盘外部变更。

## 设置工作台

设置独立窗口默认 1040×780，复用 Editor 的明暗主题、绿色操作色和 Agent 玫红标识。分类为常规、编辑器、Agent、扩展、快捷键、关于；宽度不足 760pt 时使用分类弹出菜单。全局搜索支持中英文关键词及多词匹配，直接呈现可操作的匹配分组。⌘/Ctrl+F 聚焦搜索，清空搜索恢复所选分类。

外观、语言、选择行为、垂直同步和能力门控即时保存。服务商、模型、凭据与自动应用偏好先写入 `AgentSettingsState`，明确应用后才交给 `EditorApplication.applyAISettings`；放弃更改恢复当前生效配置。`EditorSettingsSession` 由窗口持有，导航、搜索和未提交草稿不会进入持久设置，也不会被主题/语言的展示层重建丢弃。切换服务商清除未提交的密钥；密钥沿用操作系统凭据存储，环境凭据只显示来源，移除已有密钥需要界面内确认。

扩展继续通过现有检查、授权、启用、重载、禁用、撤销流程，保留访问级别、能力和包哈希。快捷键由 `EditorCommandCatalog` 读取当前 Space 的真实命令，不维护平行按键表；关于页复制应用和工作空间诊断，不包含凭据。

通过 `./guava run Editor --devtools --no-open -- --settings --project-dir /path/to/project` 可直接以设置作为主窗口启动，用同一原生 DevTools 会话验证设置。运行与测试统一使用 Guava CLI。

`SettingsWorkflowTests` 覆盖分类搜索、跨展示层重建的草稿、应用前校验、搜索快捷键、390/720/1040pt 布局，以及触摸、混合输入、RTL 和 200% 文字。服务商布局在宽窄切换时保留输入节点，不引入嵌套滚动区。

## 文档与会话

原始文本文件是持久内容。视频剪辑保存到 `.guava/media.json`，解码器、图像、设备和播放/导出任务是 session 状态。关闭项目和退出窗口会检查并保存所有三类文档，切换领域不丢弃缓冲区。文件和媒体服务只接受工程范围内的路径。媒体导出生成新的 Exports 文件，不覆盖原始素材。

当前视频工作流是可执行的顺序剪辑基础；多轨编辑、转场、媒体代理、通用语言 LSP 和跨设备完整工作站 UI 属于后续扩展。平台 SDK 的 iOS 应用宿主与桌面工作站的全部功能是两个独立支持范围。
